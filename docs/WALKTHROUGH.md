# Candidate review walkthrough

Do not submit this code until you can explain it and have personally verified it.

1. Generate a starter dataset and start the local dashboard. Explain why all names are synthetic.
2. Select EMP-000001. Compare assessed skills to role targets. Explain the gap formula.
3. Inspect the recommended sequence. Show how a completed foundation course allows an advanced course, and how an uncompleted prerequisite is inserted before an advanced course.
4. Reduce the hour limit and planning end. Explain why the path shrinks and read the excluded-candidate reasons. Budget and capacity are hard limits, not suggestions.
5. Inspect immutable event records. Find a completion without reassessment and explain why its learning outcome is not assumed.
6. Approve a path locally. Confirm new enrollments, plan events and reduced department budget. Approval does not complete the courses.
7. Record completion for an outstanding enrollment with no unmet prerequisites. Then record reassessment for a skill that course teaches. Confirm the assessed gap changes only in the second step.
8. Run the automated tests and validation. Read the ten isolated scenario inputs, then compare detector outputs to the separate labels.
9. Explain reproducibility: fixed seed, deterministic IDs, explicit simulation date, parent-first generation and checksummed ordered exports.
10. Be ready to discuss the greedy heuristic's non-optimality, lifetime capacity assumption, static simulation clock, no production authentication and lack of global cross-employee optimization.

Suggested review questions: Why is reassessment separate? How does approval avoid overspending? What happens when a prerequisite cycle exists? Which values are measured versus projected? What would you change before connecting a real HR system?
